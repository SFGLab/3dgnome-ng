# The overnight run of 2026-11-11, as it was executed

Every script, config and list the RNAPII comparison and the website smoke test used outside
the code proper, kept so the run can be read and repeated. Paths inside them are the machines'
own. The design is `design/2026-11-11-rnapii-release.md`, the plans and the execution ledger
are under `design/plans/`.

The engine on eden ran from the staged code by `PYTHONPATH`, since the shared venv holds an
editable install of the checkout's `main`.

## Files

- `watch_cells.sh`: on the laptop, waits for the nine cell line arms on eden, copies them to the
  workstation and queues the remaining readouts there (`remote/run_rest.sh`).
- `final_chain.sh`: waits for the workstation readouts and the trio readouts, gathers them and
  draws the figures with `collect_readouts.py` into `design/figures/rnapii-2026-11-12/`.
- `chain2.sh`: waits for the Micro-C slices, runs the Micro-C readouts (`remote/run_microc.sh`)
  and redraws the figures with everything into `design/figures/rnapii-2026-11-12-v2/`.
- `remote/fetch_microc.sh`: full copies of the two Micro-C maps from UCSC to the workstation.
- `trio_configs/`: the trio configs placed in eden's triosformer checkout, generated by
  `pipeline/trio_configs.py --factor CTCF|RNAPOL2 --singletons hgsvc` with this branch as
  `TRIOS_GNOME3D`, then renamed `_trio_xc_*` so no existing config was replaced.
- `arm_e/`: the ten cudaMMC chr1 models per line, drawn with seed 20261111 from the hundred in
  `models_ccd/<line>/chr1`, the rule of `e3d_export.py --subsample`.

## What is not here

The models and the readout outputs are data, on the machines above and, for the figures and the
readout tables, under `design/figures/`. Docker was not tested end to end: the account on
team-frodo cannot reach the Docker daemon. The site ran there from a venv with the image's
pinned versions.
