# Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A small, Docker deployable site where a scientist picks a cell type, a region and loop factors, optionally applies structural variants, and gets an ensemble of gnome3d structures with enhancers and promoters marked.

**Architecture:** One FastAPI app serves the form, job pages and files. One rq worker per GPU runs a job as plain function calls: region inputs from the cell type's dataset, SV rewrite by the vendored personal3d rules, an optional HiCDiffusion window, `gnome3d.cli`, then the enhancer to promoter table. Hosted data is a directory with a `catalog.json`; SV call sets are bgzipped, tabix indexed VCFs. Results are cached on disk by a hash of the request.

**Tech Stack:** Python 3.11, FastAPI, Jinja2, rq on Redis, the engine from this repository, personal3d vendored from triosformer, NGL from a CDN for the viewer, Docker Compose.

**Spec:** `design/2026-11-11-rnapii-release.md`, Part 3.

## Global Constraints

- Everything under `web/`. The engine is imported from the repository, never copied.
- No database. Catalog, jobs and cache are files under `RESULTS_DIR` and `DATA_DIR`.
- Uploads are private. A job built from an upload lives under `RESULTS_DIR/private/<token>/`, is reachable only through its secret link, never enters the shared cache, and is removed by the retention sweep after `RETENTION_DAYS` (default 14), a value the form states.
- The cell type is always chosen; it sets the base loops and the base contact map.
- HiCDiffusion is optional. Choosing it for a cell type whose `lymphoblastoid` flag is false shows the out of domain notice on the form and on the result page. The site never calls its output individual specific.
- Region span at most 3 Mb. At most 10 conformations per job.
- Tests are plain scripts under `web/tests/`, run with the project venv, in the harness style.

## Review Focus

1. A region given as a gene name that is absent, or a span over 3 Mb. Expect a form error, no job.
2. An uploaded VCF with SV types other than DEL, INS, INV, or with no SVTYPE. Expect those records skipped and counted on the result page.
3. A request identical to a finished one. Expect the cached result, no new job, for hosted inputs only.
4. A worker crash mid job. Expect the job page to show failed with the log tail, not spin forever.
5. HiCDiffusion asked for while it is not configured. Expect a form error naming the missing setting.

---

### Task 1: Catalog and regions
`web/gnome3d_web/catalog.py`, `regions.py`, tests. `Catalog.load(data_dir) -> Catalog` with `cell_types: dict[str, CellType]` (name, label, lymphoblastoid, anchors, clusters per factor, singletons, segments, centromeres, config, genes, enhancers) and `sv_sets: dict[str, SVSet]` (name, label, vcf, samples). `parse_region(text, genes) -> Region` accepting `chr:start-end` with commas, or a gene name, refusing spans over 3 Mb.

### Task 2: SVs from VCF
`web/gnome3d_web/svs.py`. `read_svs(vcf, sample, region) -> tuple[list[SV], list[SV], int]`, the two haplotypes and the count of skipped records, generic VCF with SVTYPE and SVLEN or END, INS sequence from ALT when it is sequence. Region reads through `tabix` when an index exists, a scan otherwise. Unphased genotypes go on the first haplotype.

### Task 3: Engine inputs for a request
`web/gnome3d_web/inputs.py`. `build_inputs(cell, region, factors, svs, out_dir) -> Inputs` writing loops, anchors, singletons, segments, centromeres and a config into `out_dir`, with the SVs applied by `personal3d.rewrite.apply` and the singletons and segments lifted by `personal3d.lift.Lift`, region in haplotype coordinates. With no SVs the dataset's files are cut to the region and copied.

### Task 4: Enhancer and promoter marks
`web/gnome3d_web/marks.py`. `mark_beads(beads, genes, enhancers) -> Marks` the bead index of every TSS and enhancer centre within 5 kb, and `ep_table(models, marks) -> DataFrame` per gene the ensemble mean distance to its nearest enhancer within 1 Mb.

### Task 5: The job
`web/gnome3d_web/jobs.py`. `request_key(req) -> str`, `run_job(req, results_dir) -> JobResult` running Task 3, the optional HiCDiffusion splice, `python -m gnome3d.cli`, Task 4, and writing `status.json` at each stage. `JobState` pending, running:<stage>, done, failed with log tail.

### Task 6: The app
`web/gnome3d_web/app.py`, templates. Routes: `GET /` form from the catalog, `POST /jobs` validate and enqueue or return the cached job, `GET /jobs/{id}` status and results, `GET /jobs/{id}/files/{name}`, `GET /api/catalog`. Viewer page loads each CIF in NGL with promoters and enhancers coloured.

### Task 7: Deployment
`web/Dockerfile`, `web/docker-compose.yml` (web, worker, redis; GPU on the worker), `web/README.md` covering populating `DATA_DIR`, the catalog format, adding an SV call set, HiCDiffusion, retention. `web/scripts/make_dataset.py` writes a cell type directory from this repository's prep outputs. Smoke test: compose up on a machine, one job end to end, its wall recorded as the timing measurement.
